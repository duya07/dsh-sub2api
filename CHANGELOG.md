# Changelog

## 0.2.1-dsh02.12

- The image tool no longer loses a name fight. `generate_image` is registered by dsh-image-gen as well, and the host refuses the second registrant of one name (`tool "generate_image" is already registered ...`), so whichever plugin loaded last used to lose its image tool entirely. This plugin now registers `sub2api_generate_image` by default and keeps the upstream name as an opt-in alias (`tools.generate.compatToolName`, off by default) that is only attempted while `generate_image` is still free: a name another tool already owns is left alone (`isToolNameTaken`) and the host's own duplicate rejection is swallowed (`isOwnDuplicateNameError`) instead of failing the load. Two plugins now load in either order without displacing each other.
- The `systemPrompt` section is named `tool:sub2api_generate_image` and rendered lazily, so it can only ever name tools this plugin actually registered. The names the host half and the browser half share live in the dependency-free `src/shared/image-tool-names.ts`, which the browser bundle inlines. The settings row is relabelled, states why the name changed, and gains the alias checkbox — always published explicitly, because an omitted field keeps whatever the server already stored, so a checkbox the user turns off would not stick. The alias takes effect on the next plugin load, not live.
- Ported onto the 0.2.1-dsh02.11 baseline rather than published from the 0.2.1-dsh02.7 candidate it was written against, so the .8–.11 work is intact: HTTP resilience with the idle watchdog and the bounded `429` retry, endpoint cooldowns, the probe payload verdict that replaced the `maxTokens > cap` short-circuit, the `off` level on adaptive Claude routes, and the visible probe reasons.
- Verification: 268 tests (was 253) plus server/client typechecks. The 15 new cases cover the default namespaced registration, both load orders, a conservatively yielded namespaced name, the opt-in free-name-only alias, a duplicate error swallowed for this plugin's own name and for the alias, a registry lookup that throws, the lazily rendered prompt, the browser toolview, the shared name module, and the settings and API round-trips of `compatToolName`. Mocked registries only; no real dsh-image-gen instance was co-loaded.

## 0.2.1-dsh02.11

- A failing endpoint is remembered instead of being rediscovered. `src/http-resilience.ts` gains an endpoint-level registry (`EndpointCooldownTracker`, shared process-wide as `endpointCooldowns`) keyed by the normalized gateway root, so `HTTPS://GW.example/V1/` and `https://gw.example/v1` are one endpoint. `ENDPOINT_FAILURE_THRESHOLD` (2) consecutive failures inside the `ENDPOINT_FAILURE_MEMORY_MS` (60 s) window park it; a lone failure stays a blip, and two failures an hour apart never add up.
- While parked, the next plugin-initiated request to that endpoint fails immediately with a readable reason (`endpoint cooling down after 2 consecutive failures (rate-limited); retry in 41234ms`) instead of paying another idle window, and the same note is appended to the failure that started the cooldown. One success clears the endpoint at once, and every cooldown ends by itself, so a cooldown is never a one-way door.
- Cooldown length follows the failure kind — `rate-limited` 60 s, `auth` 5 min, `quota` 15 min, `transient` 5 s, `permanent` none — an upstream-stated `retry-after` / `x-ratelimit-reset-requests` / `x-ratelimit-reset-tokens` wins over the kind default, and `MAX_ENDPOINT_COOLDOWN_MS` (15 min) caps it so a gateway stating hours cannot turn a cooldown into an outage. Memory is bounded: `MAX_TRACKED_ENDPOINTS` (64) endpoints, least recently touched evicted first, nothing written to disk.
- Wired into both plugin-owned fetch paths — the `web_search` `/responses` POST and `generate_image`'s `gatewayFetch` — which share the one registry, so an endpoint that is down for a search is known to be down for image edits. `src/reasoning-probe.ts` and the `retryPolicy` in `src/pi-ai.ts` are untouched.
- Verification: 253 tests (was 237) plus server/client typechecks. The 16 new cases cover key normalization, the threshold, the memory window, expiry, success-clears, the three kind spans, stated-delay precedence, the ceiling, the `permanent` no-op, the 64-endpoint cap with eviction, and both fetch paths end to end (a parked endpoint refused before the request is built, the reason visible on the error, recovery once the deadline passes). Mocked transports only; no real rate-limited gateway was exercised.

## 0.2.1-dsh02.10

- Plugin-initiated HTTP requests are resilient. Both plugin-owned fetch paths — the optional `web_search` `/responses` POST and `generate_image` (including the download of a remote reference image) — now run through a new `src/http-resilience.ts` and gain an idle watchdog plus one bounded `429` retry. A gateway that accepts the connection and then stops sending data is abandoned after `WEB_SEARCH_IDLE_TIMEOUT_MS` (90 s) or `IMAGE_TOOL_IDLE_TIMEOUT_MS` (120 s) of silence and reported as an idle timeout, instead of being indistinguishable from a slow-but-alive gateway until the caller's total timeout expires (`DEFAULT_IMAGE_TOOL_TIMEOUT_MS` = 180 s is a budget, not an idle detector).
- The `429` retry is bounded and conditional: **at most one** additional attempt, and only when `retry-after` (delay-seconds or HTTP-date) or `x-ratelimit-reset-requests` / `x-ratelimit-reset-tokens` states a concrete delay. A `429` without a stated delay is reported as-is and no other status is retried, so the previously documented "no hidden retries" behavior still holds for everything else.
- `retryAfterDelay(headers, now)` accepts the RFC 9110 delay-seconds and HTTP-date forms (IMF-fixdate, RFC 850, asctime) plus the vendor reset headers (`14s`, `1m30s`, `500ms`, bare or epoch seconds); any parse failure returns `undefined` and never throws. `classifyHttpFailure(status, headers?)` maps `429` / `401`,`403` / `402` / `>=500` / other `4xx` to `rate-limited` / `auth` / `quota` / `transient` / `permanent`, preferring a stated delay over the conservative per-bucket cooldown constant. `idleWatchdog(parent, idleMs)` composes the caller's signal, distinguishes an idle abort from a parent abort via `wasIdle()`, and `dispose()` clears its timer without aborting.
- The retry is an explicit, overridable policy: `DEFAULT_RATE_LIMIT_RETRY_POLICY = { enabled: true, maxRetries: 1 }`, with the hard ceiling `RATE_LIMIT_RETRY_LIMIT = 1`. Passing `{ enabled: false }` or `maxRetries: 0` restores the previous single-shot behavior. `src/reasoning-probe.ts` keeps its own pre-existing `retryAfterMs`/`Retry-After` handling and was not modified.
- Verification: 237 tests (was 213) plus server/client typechecks. The 24 new cases cover both parser forms and its failure modes, every classification bucket, the watchdog's five states, and both fetch paths end to end (a stated `429` retried exactly once, an unstated `429` not retried, a silent gateway tripping the watchdog). These use mocked transports; no real rate-limited or stalled gateway was exercised.

## 0.2.1-dsh02.9

- Reasoning probe: the `maxTokens > cap` short-circuit is gone for every protocol. It predicted `budget-limited` from the model's own output limit even though the probe always requests `maxTokens: cap`, so on OpenAI-style routes it stranded all five levels before a single request went out (the payload writes `max_output_tokens = cap`, which is exactly the accepted bound). Levels are now judged by the payload the SDK actually built; `budget-limited` survives as a real payload verdict and still carries the `maxTokens`/`cap` numbers the settings page renders.
- Verification: 213 tests plus server/client typechecks, and three mutations turn the new assertions red (re-introducing the OpenAI-only exemption, short-circuiting every protocol, dropping the budget numbers).

## 0.2.1-dsh02.8

- Reasoning probe failures are visible: the probe route returns a short classified reason (request parsing, draft parsing, key resolution, probe start) instead of the fixed `probe request unavailable` string, and the client bounds that reason where it is stored (200 characters) rather than only where it is rendered. A level that was transformed or never sent now names the wire parameter, the observed value and the expected level instead of the generic "parameter converted or not sent".
- Claude platform: an adaptive anthropic route declares the `off` level again (wire value `null`) so the host no longer drops it from the picker and thinking can be turned off. Selecting it makes pi-ai send `thinking: { type: "disabled" }` on the wire; whether a deployment accepts that flag is not verified, and OpenAI-style routes keep their verbatim `reasoning_effort` spelling.
- Verification: 212 tests plus server/client typechecks. Each fix is covered by a mutation that turns its own assertions red (probe reason classification, storage-time bound, not-exact wording, `off` declaration).

## 0.2.1-dsh02.7

- Reasoning probe: a failed no-effort control now ends the probe as "aborted" with a visible reason (was reported as "complete" with every level unknown); a rate-limited control is retried once after `Retry-After` (skipped beyond the 10-minute task lifetime); 401/403 are never retried; levels are never removed because of an abort.
- Claude platform: anthropic-messages routes write `compat.forceAdaptiveThinking: true` (per-model `thinkingMode: 'budget'` opts out); OpenAI routes unchanged.
- Added optional `web_search` provider (default off), `generate_image` reference-image editing via `/images/edits`, image-slot endpoint route persistence fix, and per-endpoint `streamIdleTimeoutMs`.
- Verification: 196 tests plus typechecks; real-gateway checks limited to one `/images/edits` and one `web_search` request (on 0.2.1-dsh02.6). The probe-abort and Claude fixes are not verified against a real gateway.

## 0.2.1-dsh02.5

- Adapted settings to the verified DSH 0.2.0-rc.2 / desktop 2.0.17 loader contract: volatile configuration, `settings.configure({ auto: false })`, and deferred initial profile synchronization.

Review completed; production full-chat validation and resolution of `upstream_error` are not claimed.
